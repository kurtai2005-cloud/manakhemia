Play the draft on a spare copy. This file is the launcher note. It does not change the game.

Do not run tools\Play-Main.ps1 for this try. That launcher always writes the player profile vc27_play_36bfd, even if the folder is a copy.
Do not run tools\Play-Usable.ps1 for this try. That launcher is a capture. It is not an interactive game, and it clears its own profile on each start.
This launcher is tools\Play-Draft.ps1. It opens ordinary Main. It does not pass --editor or --script.

GodotExe is required. This script does not look for Godot and does not install it.
The path named in the earlier Windows notes is:
C:\Users\nasa2\hd2d_test\godot\Godot_v4.7.2-stable_win64.exe
If that file is not on this machine, pass the Godot 4.7 Windows executable you already have.

ProjectDir is the spare folder that contains project.godot. Use a copy. Do not point it at the only c0df tree.
If that folder already contains override.cfg, the script stops and does not change or delete that file.
While Main is open, the script's own override.cfg points the spare project at the persistent profile vc27_draft_try.
When the window closes, the script deletes that override.cfg only if the text is still exactly the text it wrote.
It never deletes a different override.cfg.
The profile directory is not deleted. Closing the game and running the same command again opens the same save.
The script never reads or writes vc27_play_36bfd.

From the spare folder, normal draft. This keeps the existing vc27_draft_try save. It does not reset it.

- Without -Preview, the egg still takes 600 seconds and rest still waits on the real energy line. -Preview does not change those data values. It only marks a new vc27_draft_preview save.
- Eat frames still read as a face change. That was not worked on here.
- 3988 remains a partial feeding clip, not a gate.
- The eight old root-suite failures were not rerun and are not fixed.

- Hunt, dispatch, harvest, and the shop are not this loop.
- Stages after newborn stay on the normal clock. This launcher does not add them.
- If the window is killed before the script finishes, override.cfg may remain in the spare folder. The next start then stops. Do not delete an override.cfg whose text you have not read. The script will not delete one it did not just write.
