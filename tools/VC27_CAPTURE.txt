Rendered capture for the current Main and the 675 garden. Not a gameplay change.
A headless or software-GL picture is not a GPU or phone pass.

Windows command, from the folder that contains project.godot.
Do not add ExecutionPolicy Bypass.

  powershell -NoProfile -File .\tools\Capture-Loop.ps1 -GodotExe C:\Users\nasa2\hd2d_test\godot\Godot_v4.7.2-stable_win64.exe -OutputDir C:\Users\nasa2\hd2d_test\vc27_capture_out_cf0263

OutputDir must already exist, be empty, be absolute, and sit outside this project and outside AppData.
The script writes errand\ and progress\ inside it.
Profiles are only vc27_errand_capture and vc27_progress_capture.
The script deletes those two capture profiles at the start so the run is empty.
vc27_play_36bfd is rejected. The script does not read, edit, or close that profile or its process.
If override.cfg is already present, the script stops and leaves it alone.

The harness loads normal Main, sends a left click through the window ray, and lets the pet walk.
It writes PNG keyframes only after frame_post_draw, then reloads each PNG.
It exits 0 only when those files are nonempty PNGs. A timeout writes result.json with ok false and a nonzero exit.
Rows with driver=input are the clicks. Rows with driver=fixture are scripted need, clock, or care-clip setup and are not manual play.
Rows with driver=observe are pictures of the live scene after a real transition.

Minimum manual steps for the Windows operator:
  1. Close the normal Play-Main window yourself first. This script does not close it and does not touch vc27_play_36bfd.
  2. If override.cfg is still in the project, stop. Do not delete it by hand for this run, and the script will not delete a file it did not create.
  3. Create the empty output folder named above.
  4. Run the command. Let the window run. Do not click in it and do not close it early.
  5. Return the output folder. Exit 0 is not a GPU gameplay pass. The Linux selftest is llvmpipe only.

The HUD clock is TimeService wall time. A 10 hour Sim.advance changes growth and needs only. The trace records wall_clock and sim growth separately.
driver=input is a real click. driver=fixture is a scripted need, facing step, or sim advance.
Each stage writes trace_<stage>.jsonl and result_<stage>.json. trace.jsonl is appended, not replaced.
A sky-only return with the pet or house off screen is a failure, not CAPTURE_OK.

Godot is started with --rendering-method mobile and without --headless on Windows.
The Linux selftest tools/run_capture_selftest.sh uses the machine DISPLAY and does not pass --headless, because headless produced no viewport image. On this machine Vulkan lacked a surface and Godot switched to OpenGL 3, so the selftest renderer is gl_compatibility. That is not the RTX picture. The Windows command still requests --rendering-method mobile and opens a real window.
