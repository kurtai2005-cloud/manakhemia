## 3. 發現（按優先級）

### P0 — 發佈前一定要處理

**P0-1 `sfx_event_dream_talk` 響度同「睡眠中細聲夢話」唔匹配**
- 量度：-16.1 LUFS（README -15.9）、峰值 -2.9 dBFS；同場景嘅 `sfx_pet_sleep_breath_loop` 係 -22.2 LUFS／峰值 -6.5 dBFS。夢話比背景呼吸聲大 **6.6 LU／峰值高 3.6 dB**，同其他事件音（-15 至 -16 LUFS）同級，但事件音多數喺日間清醒狀態播，夢話係少數喺睡眠狀態播嘅。夜間 23:00–07:00 突然彈出，容易變成「叮醒玩家」。
- 其他方面符合夢話：頻譜低（重心 551 Hz，>4 kHz 只有 0.7%）、氣聲度高（HNR 0.87，寵物聲普遍 0.93–0.97）、基頻 405–513 Hz 平緩起伏、尾段 1.2–1.8 s 由 -18 漸弱到 -43 dBFS（漸弱成立）。
- 注意：包絡其實係 0.5–0.8 s 先最大聲（100 ms RMS -10.2 dBFS），之後跌落去，再有一個較細嘅 1.0–1.1 s 峰，唔係由頭到尾遞減。屬可接受嘅「兩個音節」形態。
- README 建議 ×0.7（-3.1 dB）：只可以拉到約 -19.2 LUFS，仍然比睡眠 loop 大 3 LU，**唔夠**。
- **建議修法**：烘焙／runtime 降 **-7 dB**（音量係數 ≈0.45），目標約 -23 LUFS、峰值約 -10 dBFS，同 breath loop（-22）同一層；播放時避開 `sfx_sleep_on` 同步。保留現有漸弱，無需改長度。若遊程有「睡眠場景音量匯流」（bus），可以直接設該 bus -7 dB。

### P1 — 應該修，或者先聽過再定

**P1-1 `sfx_pet_grumpy` 起音偏硬＋逐下由靜音爆出（startle 風險）**
- 量度：起音 9 ms（`pet_content` 399 ms；`happy` 11 ms、`curious` 7 ms，所以唔係全組最硬）；3 下脈衝每下由數碼靜音升到滿位，包絡跳幅達 +12 dB（第 1 下）、+66 dB（第 2 下）。有 -8.5 dBFS 峰值，同 `happy` 同級。
- 為何唔係「嚇人」：>4 kHz 0.0%、2–5 kHz 0.3%、重心 481 Hz，冇刺耳成分；音高 380–500 Hz 下垂，語調係「悶哼」而唔係「尖叫」。
- 風險主要係：① 玩家連點觸發（建議 1.5 s 內 ≥4 下、冷卻 3 s）時，如果玩家本身已經焦躁，硬起音 + 脈衝感會加劇煩躁；② 3 下脈衝約 6 Hz 節奏，重複聽可能變「煩」多過「嚇」。
- **建議修法**（改動細，保持「生氣但可愛」）：
  1. 每下「噗」加 **12–15 ms** 餘弦淡入（現時約 9 ms 起升），整體起音由 9 ms 放慢到 ~15 ms；
  2. 整體增益 **-1.5 dB**（峰值 -8.5 → -10 dBFS，同 `uncomfortable` -9.8 一致）；
  3. 如果真人聽仍覺突兀：第 1、2 下「噗」再 -2 dB，保留最尾「噗嚕～」做重點。
  4. 程式端：冷卻 3 s 保留；同一日觸發 ≥3 次後，音量逐次 -1.5 dB（下限 -4.5 dB）。
- **需耳測**：「粗糙」「鼻音」呢類質感只有 12% 嘅 19 Hz 調變可量，聽感未知。

**P1-2 `sfx_pet_uncomfortable` 音高帶落喺人類嬰兒哭聲基頻區（341–464 Hz）——需耳測，量度上唔嚇人**
- 量度全部偏安全：峰值 -9.8（寵物聲最細）、-17.4 LUFS、起音 31 ms、>4 kHz 0.0%、粗糙度 1.3%、HNR 0.94（乾淨、無沙啞）。2 句嘅「嗚…嗚」下垂 5.2 半音，中間有約 60 ms 靜音。
- 風險：嬰兒哭聲基頻約 300–600 Hz 且多為下垂句型；若真人覺得「似小朋友喊」，可能有人覺得內疚或不安（不一定係壞事——「不適」本來就想帶關心感）。呢點量度確認唔到，純屬基於音高帶嘅推測。
- **建議**：先聽。如覺得太似哭聲：**降 2–3 半音**（約 280–390 Hz，唔好升高，升高會更似哭）並 -1 dB；如果覺得唔夠「不適」就唔使改。
- **現時唔需要改檔**；列做 P1 純粹因為屬「頭 3 個耳測項目」。

### P2 — 可選／低風險

**P2-1 `sfx_event_shiny_day`（3.00 s）長度**
- 包絡（50 ms RMS）：0–0.1 s 淡入（-45 dBFS 起），0.4–0.8 s 達峰值（約 -12 dBFS），之後緩降；喺峰值 -6／-10／-15／-20 dB 以內嘅最後時刻分別係 **1.85／2.40／2.65／2.80 s**。即係最後約 0.35–0.6 s 已經係極輕尾韻。
- 對比：`fade_light` 3.0 s（-6/-10/-15/-20 dB 時刻 2.10/2.35/2.55/2.75）、`evolve` 2.9 s、`hatch` 2.9 s、`treasure_hunt` 2.5 s、`meteor_night`／`rainbow` 2.4 s。所以 3.0 s 唔係特別長；且只喺 3% 閃光日播放。
- 其他：README 話有 64 粒隨機高頻閃光，但 >4 kHz 能量只佔 2.5%、2–5 kHz 佔 20.6%（唔刺耳）；響度 -15.3 LUFS 同事件組一致；有 100 ms 淡入，起音 367 ms（柔和，唔會 startle）；頭 0.1 s 近乎無聲，觸發同畫面對位時要留意約 100 ms 延遲。
- **建議（可選）**：若想收短，剪到 **2.6 s**，由 2.35 s 起做 250 ms 餘弦淡出（只會損失峰值 -15 dB 以下嘅尾韻）。唔剪亦可接受；UI 提示條記得唔好在 3 s 前自動關閉。

**P2-2 5 個超短 UI 音偏大聲（+3.0 至 +3.9 LU，循環等效值）**
- `sfx_tap`（-11.4）、`sfx_confirm`（-11.9）、`sfx_hit`（-12.0）、`sfx_cancel`（-12.2）、`sfx_error`（-12.3），距全 SFX 中位數 -15.3 LUFS 超過 3 LU。因為全部 <0.35 s，人耳時間積分會令感知比數值細，所以屬資訊性提示，唔係缺陷。
- 影響：同寵物聲（-17.2 至 -17.8）比較差 5–6 LU。若 UI 點擊同寵物摸摸（`pet_touch_a/b` -17.3）同時播，UI 會蓋過寵物聲。
- **建議**：真機疊音測試，若唔順耳，UI 5 音統一 -2 dB（目標約 -14 LUFS）。唔屬本次寵物聲範圍，轉交 遊音 決定。

**P2-3 `sfx_event_sulk`（鬧脾氣）比 `pet_grumpy` 大 2.2 LU 且有跺腳**
- -15.1 LUFS／峰值 -3.8 dBFS、4 個脈衝（起升跳幅 +29 至 +55 dB）。若同一場景連續出現 grumpy + sulk，後者會突然變大。建議程式避免兩者 3 s 內連播；或 sulk 降 -2 dB。

**P2-4 `sfx_env_sunbathe_loop` 低頻佔比高**
- 38% 能量喺 <150 Hz（C2／C3 pad），手機喇叭多數放唔出，實際聽到會比 -23 LUFS 更細聲、較薄。屬設計取捨；建議真機聽一次，必要時加 +2 dB 或配耳機測試。

兩個 loop 接縫變化都細過檔內正常變化；`sunbathe` 首尾樣本非零（-0.0156／-0.0131）但連續，唔使淡入淡出。呼吸 loop 起尾本身係靜音谷（-50 dBFS），自然接駁。**注意**：loop 播放必須用 sample-accurate 無縫循環（Web Audio `loop=true`／Godot loop），唔好經 MP3 或串流播放，否則會多出 gap。

## 6. 其他量度備註
- 寵物／事件檔（非 loop）結尾 5 ms 峰值 ≤ -43 dBFS；開頭 1 ms 峰值 ≤ -23 dBFS（最高係 `event_gift_return`）。UI 短音（`tap`／`hit`／`mg_catch` 等）開頭 1 ms 峰值高至 -4 至 -10 dBFS，屬打擊音設計，唔係本次範圍。未見起尾 click。
- 檔案係 Vorbis；本審查喺解碼後 float 計算，peak／TP 已反映 codec 後數值。
- ebur128 對 <0.4 s 嘅檔唔出值（-70），所以第 2、4 節用循環等效值；未做 A 加權或心理聲學響度（sone）建模。
- 基頻估算對氣聲／噪音／多音鐘聲唔可靠（`dream_talk` 後段、`shiny_day`、loop 只作參考）。
